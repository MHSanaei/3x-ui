3x-ui can drive a Telegram bot for monitoring, alerts, backups, and remote
management. It also doubles as a customer-facing self-service channel: a client
links their own Telegram account to a subscription and then fetches their
configs, QR codes, usage and expiry without ever touching the panel.

Every update resolves to one of three levels, and commands are allowlisted per
level rather than denied one by one:

| Level        | Who they are                                  | What they may run                                            |
| ------------ | --------------------------------------------- | ------------------------------------------------------------ |
| **stranger** | Not an admin, no subscription bound           | `/start` only — nothing else answers, so the panel stays invisible |
| **client**   | A Telegram account bound to a subscription    | `/start`, `/help`, `/status`, `/id`, `/usage`, `/pm`, `/cancel` |
| **admin**    | An ID listed in `tgBotChatId`                 | Everything, including all admin flows                         |

An admin outranks their own client bindings, so an operator who also holds a
config still reaches the admin console.

## Set it up

<Step>
### Create a bot

Message [@BotFather](https://t.me/BotFather), send `/newbot`, and copy the **bot
token**.
</Step>

<Step>
### Find your Telegram ID

Get your numeric Telegram user ID (the bot's own `/id` command reports it once
connected). This is your **admin** ID.
</Step>

<Step>
### Configure the panel

In Panel Settings, enable the Telegram bot and set the **token** and **admin chat
ID(s)** (comma-separated). Save, then message your bot.
</Step>

## Commands

These appear in the Telegram command menu: `/start`, `/help`, `/status`, `/id`.
Additional commands:

| Command            | Who            | Action                                                       |
| ------------------ | -------------- | ------------------------------------------------------------ |
| `/start`           | anyone         | Greeting and menu. With an invite token (`/start <subId>`) it binds the account |
| `/help`            | client, admin  | The help hub; admins can rewrite its text with `/sethelp`    |
| `/status`          | client, admin  | Confirm the bot is alive                                     |
| `/id`              | client, admin  | Show your Telegram numeric ID                                |
| `/usage <arg>`     | client, admin  | Admins search clients; clients look up their own usage       |
| `/pm`              | client, admin  | Message the admin; admins reply inline from the notification |
| `/cancel`          | client, admin  | Abort a pending message to the admin, or a pending admin reply |
| `/inbound <remark>`| admin          | Show an inbound's details                                    |
| `/restart`         | admin          | Restart Xray                                                 |

Admins also get inline-button flows, filed into five sections: server usage and
sorted traffic reports, resetting traffic, DB backups, ban logs, listing
inbounds/clients, online clients, "depleting soon", a full **add-client**
wizard, roster search and filters, bulk extend/disable, broadcast, and a
**Bot Settings** menu for the options in the table below.

## Customer self-service

Binding is what turns a stranger into a client. From a client's card in the
admin console, **Invite link** produces a deep link of the form:

```
https://t.me/<your_bot>?start=<subId>
```

The customer opens it, Telegram sends `/start <subId>`, and the bot binds their
Telegram account to that subscription and notifies the admin. From then on they
get a keyboard with:

- **My Configs** — the config list, each delivered with its own QR code and
  per-platform setup guide.
- **Usage** — a single message with expiry and traffic that refreshes in place.
- **Renew** — asks the admin to extend the subscription, plus a switch to stop
  renewal reminders.
- **Help** and **Message admin** — the help hub, and a direct line to the
  operator with inline replies.
- **Settings** — per-user language, independent of the panel's `tgLang`.

<Callout type="info">
  One Telegram account may hold several subscriptions, up to `tgBotMaxBindings`
  (default 5). Set it to `1` for the original one-config-per-account rule, or
  `0` to remove the ceiling. The limit counts subscriptions, not client records,
  and every per-config action is re-checked against ownership — a client can
  only ever act on a config bound to their own Telegram ID.
</Callout>

Customers are told when their traffic quota passes 80% and 95%. A daily pass
runs at `tgBotDailyHour` and sends renewal reminders; admins can trigger it
early with **Remind now**, which first previews how many customers are due and
then claims the day so the scheduled run cannot repeat it.

## Reports & alerts

- **Periodic report** — on the `tgRunTime` schedule (default `@daily`), the bot
  sends admins server usage (host, versions, uptime, load, memory, online
  clients, traffic), a list of exhausted/expiring clients, and — if
  `tgBotBackup` is on — a database + Xray config backup. Clients linked by
  Telegram ID get their own expiry/quota warnings.
- **Event alerts** — selected by `tgEnabledEvents` (default `login.attempt,cpu.high`):

  | Event           | When                                                    |
  | --------------- | ------------------------------------------------------- |
  | `login.attempt` | A panel login succeeds or fails (with IP and username)  |
  | `cpu.high`      | CPU exceeds `tgCpu` percent (default 80)                |
  | `memory.high`   | Memory exceeds `tgMemory` percent (default 80)          |
  | `xray.crash`    | Xray-core crashes                                       |
  | `outbound.down` / `outbound.up` | An outbound goes down / recovers        |
  | `node.down` / `node.up`         | A node goes offline / comes back        |

The warning lead times come from `expireDiff` (days before expiry) and
`trafficDiff` (GB of quota remaining); both default to `0` (off).

## Settings

| Setting        | Default                    | Meaning                                        |
| -------------- | -------------------------- | ---------------------------------------------- |
| `tgBotEnable`  | `false`                    | Master on/off.                                 |
| `tgBotToken`   | _(secret)_                 | Bot API token.                                 |
| `tgBotChatId`  | _(none)_                   | Comma-separated **admin** Telegram IDs.        |
| `tgBotProxy`   | _(none)_                   | `socks5://`, `http://`, or `https://` proxy.   |
| `tgBotAPIServer` | _(default)_              | Custom Telegram Bot API server.                |
| `tgRunTime`    | `@daily`                   | Report schedule (cron / `@daily` / `@every …`).|
| `tgBotBackup`  | `false`                    | Attach a DB backup to the periodic report.     |
| `tgCpu` / `tgMemory` | `80` / `80`          | CPU / memory alert thresholds (percent).       |
| `tgLang`       | `en-US`                    | Bot language.                                  |
| `tgEnabledEvents` | `login.attempt,cpu.high`| Which events to deliver.                       |
| `tgBotMaxBindings` | `5`                     | Subscriptions one Telegram account may hold (`1` = old rule, `0` = unlimited). |
| `tgBotAllowSelfReset` | `false`              | Let customers reset their own configs. The reset knocks every one of that client's devices offline until re-import. |
| `tgBotDailyHour` | `8`                       | Hour of day the customer-facing daily pass runs, kept apart from `tgRunTime`. |
| `tgBotSilentNotices` | `false`               | Deliver customer notices without a notification sound. |

The last four are set from the bot's own **Bot Settings** menu rather than Panel
Settings, and are stored as ordinary settings rows — enabling them needs no
database migration.

<Callout type="warn">
  The bot token controls your bot — keep it secret and only add **trusted** admin
  chat IDs. Login alerts never include passwords.
</Callout>

<Callout type="info">
  Email (SMTP) notifications mirror the same events (`smtpEnabledEvents`) if you'd
  rather receive alerts by email — configure SMTP in Panel Settings.
</Callout>
