**Panel Settings** controls how the panel itself is served and secured (separate
from your inbounds and clients). Settings are stored as key/value pairs; the
defaults below come straight from the panel source. Secrets (tokens, passwords)
are shown only as a "set / not set" indicator and are never returned to the
browser in full.

## Web server

| Setting             | Default                 | Meaning                                                                 |
| ------------------- | ----------------------- | ----------------------------------------------------------------------- |
| `webPort`           | `2053`                  | Panel port (1–65535). The `XUI_PORT` env var overrides it at runtime.   |
| `webListen`         | _(all interfaces)_      | Bind the panel to a specific IP.                                        |
| `webBasePath`       | `/`                     | URL path the panel is served under (always normalized to `/…/`).        |
| `webCertFile` / `webKeyFile` | _(none)_       | TLS certificate + key. When both are set, the panel serves **HTTPS**.   |
| `sessionMaxAge`     | `360`                   | Session lifetime in **minutes** (default 6 hours).                      |
| `trustedProxyCIDRs` | `127.0.0.1/32,::1/128`  | IPs/CIDRs whose forwarded headers (real client IP) are trusted. A custom value also controls forwarded host and scheme in subscription links; include the subscription proxy or set `subURI` to override those links. |
| `panelOutbound`     | _(none)_                | Route the panel's own egress (update checks, Telegram, geo/sub fetches) through a named Xray outbound. |

After changing the port or base path, the panel URL becomes
`http(s)://<server>:<port><web-base-path>`. You can preset the base path on first
launch with [`XUI_INIT_WEB_BASE_PATH`](/docs/reference/env-vars).

### TLS

Serving the panel over HTTPS protects your credentials in transit. Either set
`webCertFile` + `webKeyFile` — the [`x-ui` SSL menu](/docs/config/ssl-certificates)
can obtain a Let's Encrypt certificate for you — or terminate TLS at a
[reverse proxy](/docs/operations/reverse-proxy).

<Callout type="warn">
  Never expose the panel over plain HTTP on the public internet. Use TLS, a
  non-default port, and a long random web base path.
</Callout>

## Display

| Setting          | Default                                          | Meaning                                                       |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------- |
| `pageSize`       | `25`                                             | Rows per page in lists (`0` disables pagination).             |
| `expireDiff`     | `0`                                              | Days before expiry to start warning.                          |
| `trafficDiff`    | `0`                                              | Percent of quota remaining at which to start warning.         |
| `remarkTemplate` | `{{INBOUND}}-{{EMAIL}}\|📊{{TRAFFIC_LEFT}}\|⏳{{DAYS_LEFT}}D` | Default client remark template (see [Share links](/docs/config/share-links#remark-template-variables)). |
| `timeLocation`   | `Local`                                          | Time zone for stats and expiry.                               |
| `datepicker`     | `gregorian`                                      | Calendar for date inputs (Gregorian or Jalali/Persian).       |

## Network traffic interface

In **Settings → General → Panel settings**, use **Network Traffic Interface**
to select the source of system traffic totals and throughput. It does not change
Xray client quotas, client billing counters, or inbound traffic accounting.

| Setting | Default | Meaning |
| --- | --- | --- |
| `networkTrafficMode` | `legacy` | `legacy`, `auto`, or `manual`. |
| `networkTrafficInterface` | _(empty)_ | Exact interface name used in manual mode, such as `eth0`, `ens3`, or `enP6129s1`. |

- **All interfaces (Legacy)** remains the default on new installations and upgrades.
  It sums the same interfaces as before, excluding the existing loopback and virtual
  interface prefixes. Stacked interfaces, such as Azure's synthetic interface and
  its SR-IOV function, can represent the same traffic and be counted twice.
- **Automatic** reads Linux's main routing table through netlink without executing
  shell commands or sending network probes. Among usable default routes, IPv4 is
  preferred to IPv6. The lowest route metric wins within that family; equal metrics
  use the interface name as a deterministic tie-breaker. IPv6-only systems use their
  IPv6 default route. ECMP also selects a single usable next hop.
  Only the selected interface is counted, including virtual
  interfaces when the default route uses one. Policy-routing tables and
  destination-specific route selection are outside this primary-route heuristic.
- **Manual** lists interfaces dynamically and counts only the exact selected name.
  Explicit selections bypass the legacy virtual-interface exclusions. The backend
  validates that the selected interface exists when settings are saved.

Automatic detection runs on each status collection, normally every two seconds,
so route changes take effect on the next sample. If detection fails, a selected
interface disappears, or counters cannot be read, the network metrics are marked
unavailable. The dashboard and bot reports show this state, and histories omit
unavailable samples. No other interface or aggregation mode is substituted.
When the interface returns, normal collection resumes automatically.

Speed and packet-rate calculations start from a new baseline after a mode change,
interface change, detected device recreation, counter decrease/reset, or a failed
sample. The first comparable sample resumes normal rates. Totals remain the
selected kernel counters, rather than monthly billing totals; existing history
can contain samples collected under previous interface selections.

Each panel, including a sub-node, selects interfaces in its own network namespace.
In a Docker bridge network these are container interfaces, not host-wide traffic.
Host interfaces are visible only when the deployment shares the host network
namespace. Reading interfaces, routes, and counters requires no `CAP_NET_ADMIN`,
firewall rules, nftables setup, Python process, or additional daemon. The existing
Docker capabilities needed by other features are unrelated to this setting.

Legacy and manual modes remain available on supported non-Linux platforms.
Automatic mode currently requires Linux; other platforms show an explicit
detection error and should use manual or legacy mode.

Settings persist in the existing key/value settings table; no schema migration is
needed. Database backups retain the selection. **Keep this machine's settings** on
import preserves the destination panel's selection, including a missing setting
that uses the legacy default. An imported manual interface that does not exist
is reported as unavailable rather than replaced.

Older settings API clients that omit the new fields preserve the current selection.
Send an explicit `networkTrafficMode: "legacy"` to restore legacy aggregation.

Authenticated administrators can list interfaces with
`GET /panel/api/server/networkInterfaces`. It uses the existing response envelope
and returns interface names/up state plus the automatic choice or detection error.
Status responses retain `netTraffic` and `netIO` and add `networkInterface`
(`mode`, `name`, `available`, `error`), together with the existing
`unavailableMetrics` list when collection fails. Older status responses without
this metadata remain compatible.

The default-route selection approach was inspired by
[IPv6Monitor](https://github.com/HamedSanaei/ipv6monitor). Its Python daemon,
database, and nftables accounting are not used. Separate IPv4/IPv6 traffic counters
are outside this feature's scope: the selected interface's counters include both.

## Security & authentication

Credentials, two-factor auth, the brute-force limiter, sessions, and LDAP are
covered in [First login](/docs/guide/first-login) and
[Security](/docs/operations/security). In short:

- Passwords are stored as **bcrypt** hashes; changing them logs out all sessions.
- **2FA (TOTP)** can be required at login.
- An **LDAP** fallback can authenticate users when the local password check fails.
- API access uses **API tokens** managed under Panel Settings (see the
  [API reference](/docs/reference/api/api-tokens)).
