Панель умеет отдавать клиентам готовый профиль маршрутизации: какие сайты и
IP идут напрямую, какие через прокси, а какие блокируются. Формат профиля
зависит от приложения:

| Приложение        | Формат профиля                       | Где задаётся в панели                 |
| ----------------- | ------------------------------------ | ------------------------------------- |
| **Happ**          | JSON (в виде `happ://` ссылки)       | Настройки подписки → вкладка **Happ** |
| **Clash / Mihomo**| YAML (правила, группы, провайдеры)   | Вкладка **Clash / Mihomo**            |
| **Incy**          | JSON (в виде `incy://` ссылки)       | Вкладка **Incy** → **Маршрутизация**  |

Во всех трёх полях можно указать **либо сам профиль** (inline), **либо одну
постоянную HTTPS‑ссылку** на файл — например, на raw‑gist. Ссылку удобно
использовать, чтобы менять правила, не заходя в панель.

## Как панель работает с удалённой ссылкой

В полях Happ и Clash / Mihomo значение из одной строки `https://...` считается
удалённым источником, который панель скачивает сама:

- панель скачивает файл **в фоне** и кэширует его на 10 минут; запрос подписки
  никогда не ждёт источник;
- файл проверяется; если он невалиден, панель **продолжает отдавать последнее
  рабочее значение** и пишет предупреждение в лог;
- допустим только `https://`, без логина/пароля в URL, адрес должен вести на
  публичный хост (локальные и внутренние адреса блокируются);
- редиректы допускаются (до 5), но только на `https://`;
- лимиты: Clash — 2 МиБ; Happ — 16 КиБ ответа и 8 КиБ значения после
  кодирования в Base64 (около 6 КиБ JSON); таймаут запроса 6 секунд.

Поле Incy работает иначе: панель никогда не скачивает ссылку Incy. Она только
проверяет, что это `https://` без логина/пароля, и передаёт ссылку приложению,
которое само загружает и обновляет профиль (см. раздел про Incy ниже).

Совет: используйте **raw**‑ссылку (`gist.githubusercontent.com/.../raw/...`),
а не страницу gist.

## Happ

### Где вводить

**Настройки → Подписка → Happ → Маршрутизация и правила**:

1. включите **Включить маршрутизацию** (заголовок `Routing-Enable: true`);
2. вставьте в поле **Правила маршрутизации** одно из:
   - готовую ссылку `happ://routing/onadd/<base64>`;
   - постоянную HTTPS‑ссылку на **JSON** или на файл с `happ://` ссылкой;
   - `happ://routing/off` — чтобы отключить маршрутизацию на клиенте.

Панель отправляет значение клиенту в заголовке `Routing`. Если в файле по
HTTPS лежит обычный JSON, панель сама превращает его в
`happ://routing/onadd/<base64>`. Источник может также отвечать редиректом
на `happ://...` — это тоже принимается (так работают сервисы вроде
routing.help).

Если поле пустое, но заполнен **профиль маршрутизации JSON‑подписки**
(`subJsonRoutingRules`), то он же автоматически уходит в заголовок `Routing`.

Быстрее всего начать с **Пресетов маршрутизации** (Iran Bypass, China Direct,
Global, LAN bypass; опционально с блокировкой рекламы) или с
**Визуального конструктора правил** — он загружает текущий профиль и позволяет
править списки или весь JSON.

### Формат JSON

Профиль — это один JSON‑объект. Значения‑флаги Happ записывает строками
(`"true"`, `"false"`), а списки — массивами строк.

```json
{
  "Name": "My Routing",
  "GlobalProxy": "true",
  "RouteOrder": "block-proxy-direct",

  "RemoteDNSType": "DoH",
  "RemoteDNSDomain": "https://cloudflare-dns.com/dns-query",
  "RemoteDNSIP": "1.1.1.1",
  "DomesticDNSType": "DoH",
  "DomesticDNSDomain": "https://dns.alidns.com/dns-query",
  "DomesticDNSIP": "223.5.5.5",
  "DnsHosts": {
    "cloudflare-dns.com": "1.1.1.1",
    "dns.alidns.com": "223.5.5.5"
  },

  "DirectSites": ["geosite:private", "geosite:cn", "domain:example.cn"],
  "DirectIp": ["geoip:cn", "geoip:private", "192.168.0.0/16"],
  "ProxySites": [],
  "ProxyIp": [],
  "BlockSites": ["geosite:category-ads-all"],
  "BlockIp": [],

  "DomainStrategy": "IPIfNonMatch",
  "FakeDNS": "false",
  "UseChunkFiles": "true"
}
```

| Поле | Тип | Смысл |
| ---- | --- | ----- |
| `Name` | строка | Название профиля в приложении. |
| `GlobalProxy` | `"true"`/`"false"` | Глобальный режим: всё, что не попало в правила, идёт через прокси. |
| `RouteOrder` | строка | Порядок проверки групп через дефис: `block-proxy-direct`, `block-direct-proxy` и т. п. Побеждает **первая** сработавшая группа. Допустимые слова: `block`, `proxy`, `direct`; повторы игнорируются. |
| `DirectSites` / `ProxySites` / `BlockSites` | массив строк | Домены: напрямую / через прокси / блокировать. |
| `DirectIp` / `ProxyIp` / `BlockIp` | массив строк | IP и подсети — те же три группы. |
| `RemoteDNSDomain`, `RemoteDNSIP`, `RemoteDNSType` | строка | DNS для проксируемого трафика (`DoH` и адрес `https://.../dns-query`). |
| `DomesticDNSDomain`, `DomesticDNSIP`, `DomesticDNSType` | строка | DNS для «прямых» доменов. |
| `DnsHosts` | объект «имя → IP» | Статические записи, чтобы не резолвить DoH‑хосты через сам DNS. |
| `DomainStrategy` | строка | Стратегия Xray: `AsIs`, `IPIfNonMatch`, `IPOnDemand`. |
| `FakeDNS`, `UseChunkFiles` | `"true"`/`"false"` | Расширения Happ; панель передаёт их клиенту как есть. |

Неизвестные поля **не теряются** — панель и редактор сохраняют их и передают
Happ.

### Формат записей в списках

Записи — синтаксис Xray‑маршрутизации:

| Запись | Что совпадает |
| ------ | ------------- |
| `geosite:category-ads-all` | Категория из `geosite.dat`. |
| `geosite:private`, `geoip:private` | Локальные/приватные адреса. |
| `geoip:ir`, `geoip:cn` | Страна из `geoip.dat`. |
| `domain:example.com` | Домен и все его поддомены. |
| `full:www.example.com` | Только этот домен. |
| `keyword:ads` | Домен, содержащий подстроку. |
| `regexp:\\.ru$` | Регулярное выражение. |
| `10.0.0.0/8`, `1.2.3.4` | Подсеть CIDR или один IP. |

Запись без префикса трактуется как подстрока домена — для точности пишите
`domain:`. Категории `geosite:`/`geoip:` должны существовать в `.dat` файлах
на клиенте; панель передаёт их в заголовке `Routing`, чтобы Happ подтянул
нужные гео‑файлы.

### Как собрать `happ://` ссылку вручную

Ссылка — это префикс и JSON в Base64 (UTF‑8):

```text
happ://routing/onadd/<base64 от JSON>
```

`onadd` добавляет профиль и сразу включает его; `add` — только добавляет.
Панель принимает base64 в обычном и URL‑safe виде, с `=` и без. Из PowerShell:

```powershell
$json = Get-Content .\routing.json -Raw -Encoding UTF8
$b64  = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($json))
"happ://routing/onadd/$b64"
```

Итоговое значение не должно превышать 8 КиБ, ссылка должна быть в одну строку.

### Что панель делает с этим JSON в JSON‑подписках

Для клиентов, которые читают конфиг из тела JSON‑подписки, профиль **вшивается**
в разделы `dns` и `routing`. Правила такие:

- порядок групп — из `RouteOrder`, по умолчанию `block`, `direct`, `proxy`;
- пустые списки пропускаются, в конце всегда добавляется правило «всё остальное
  → `proxy`»;
- `DomainStrategy` по умолчанию `IPIfNonMatch`;
- DNS: для `DirectSites` добавляется «внутренний» DNS (`DomesticDNS*`, по
  умолчанию `https://77.88.8.8/dns-query`), для остального — `RemoteDNS*`
  (по умолчанию `https://8.8.8.8/dns-query`); `DnsHosts` копируется в `dns.hosts`.

Поля должны иметь точный тип: строка — строка, список — массив строк, `DnsHosts` —
объект «строка → строка». Иначе профиль отбрасывается и подписка отдаётся с
маршрутизацией по умолчанию (в лог пишется предупреждение).

## Clash / Mihomo

### Где вводить

**Настройки → Подписка → Clash / Mihomo**:

1. включите **Включить маршрутизацию**;
2. заполните **Глобальные правила маршрутизации** — inline‑текстом или одной
   HTTPS‑ссылкой на YAML.

Правила применяются к профилям по адресам `subClashPath` и `/mihomo/<sub-id>`.
Эндпоинт `/clash-legacy/` (Clash for Windows) всегда отдаёт минимальный профиль
и **игнорирует** эти настройки.

### Что уже есть в профиле

Панель собирает базу сама:

```yaml
proxies:            # все ваши узлы, имена — их ремарки
  - { name: "node-1", type: vless, ... }
proxy-groups:
  - name: PROXY     # select: все узлы + DIRECT
    type: select
    proxies: [node-1, DIRECT]
rules:
  - MATCH,PROXY
```

Ваши правила можно направлять на группу **`PROXY`**, на `DIRECT`, на `REJECT`
либо на любую группу, которую вы сами объявили.

### Вариант 1: inline‑значение

Три допустимых формы.

**А) Просто строки правил** (можно с комментариями `#`):

```text
# рекламу блокируем
GEOSITE,category-ads-all,REJECT
DOMAIN-SUFFIX,example.com,DIRECT
GEOIP,RU,DIRECT,no-resolve
```

**Б) YAML‑список:**

```yaml
- GEOSITE,category-ads-all,REJECT
- DOMAIN-SUFFIX,example.com,DIRECT
- GEOIP,RU,DIRECT,no-resolve
```

**В) YAML‑карта.** Ключ `rules` объединяется с базовыми правилами, любые другие
ключи (`proxy-groups`, `rule-providers`, `dns`, `sniffer`, …) **заменяют**
одноимённые ключи профиля целиком:

```yaml
proxy-groups:
  - name: PROXY
    type: select
    proxies: [DIRECT]        # осторожно: заменяет группу PROXY целиком
rule-providers:
  ads:
    type: http
    behavior: domain
    format: yaml
    url: https://example.com/ads.yaml
    path: ./ruleset/ads.yaml
    interval: 86400
rules:
  - RULE-SET,ads,REJECT
  - GEOIP,RU,DIRECT
```

Как объединяются правила:

- если в ваших правилах **нет** `MATCH`, они ставятся **перед** базовым
  `MATCH,PROXY` — всё остальное пойдёт через прокси;
- если `MATCH` есть, ваш список **полностью заменяет** базовые правила.

В inline‑режиме проверка мягкая: содержимое YAML‑карты копируется как есть,
поэтому ошибки в именах групп вы увидите только в клиенте.

### Вариант 2: HTTPS‑ссылка на YAML

Здесь панель строже — она **проверяет** файл и только затем использует.
Из документа берутся только три ключа:

| Ключ | Что делает |
| ---- | ---------- |
| `rules` | Правила — объединяются по тем же правилам, что выше. |
| `proxy-groups` | Группы: одноимённые заменяют базовые, остальные базовые сохраняются. |
| `rule-providers` | Провайдеры правил. |

Ключи `dns` и `sniffer` берутся, **только если включён** переключатель
**DNS из удалённых правил** (`subClashRemoteDNS`) — включайте его лишь для
шаблона, которому доверяете: он меняет DNS клиента. Все остальные ключи
(`proxies`, `proxy-providers`, `port` и т. д.) игнорируются. Узлы всегда
остаются вашими.

Рабочий пример файла:

```yaml
proxy-groups:
  - name: Streaming
    type: select
    proxies: [PROXY, DIRECT]
  - name: Auto
    type: url-test
    url: https://www.gstatic.com/generate_204
    interval: 300
    proxies: [PROXY]

rule-providers:
  ru-direct:
    type: http
    behavior: domain
    format: yaml
    url: https://example.com/ru-direct.yaml
    path: ./ruleset/ru-direct.yaml
    interval: 86400

rules:
  - RULE-SET,ru-direct,DIRECT
  - DOMAIN-SUFFIX,netflix.com,Streaming
  - GEOIP,PRIVATE,DIRECT,no-resolve
  - MATCH,PROXY
```

Что обязательно проверяется (при нарушении файл отклоняется, остаётся прошлая
рабочая версия):

- документ — YAML‑карта хотя бы с одним из `rules`, `proxy-groups`,
  `rule-providers`;
- каждая группа — карта с непустыми `name` и `type`, имена **уникальны**;
- в группах **нельзя** использовать `use:` (proxy‑providers не поддерживаются);
- каждая ссылка в `proxies:` группы, цель каждого правила и `proxy:` у
  провайдера должны указывать на группу из этого же файла, на `PROXY` или на
  встроенные `DIRECT`, `REJECT`, `REJECT-DROP`, `REJECT-TINYGIF`, `PASS`,
  `GLOBAL`. Удалённый файл проверяется сам по себе, поэтому имя конкретного
  узла в нём не пройдёт проверку;
- `RULE-SET,<имя>,<цель>` требует провайдера с таким именем в `rule-providers`;
- каждое правило — непустая строка вида `ТИП,значение,цель`; после цели
  допускаются флаги `no-resolve` и `src`;
- ограничения размера: 2 МиБ ответа и ограничение на вложенность и объём после
  разворота YAML‑алиасов.

Так как имена узлов зависят от ремарок клиентов, надёжнее всего ссылаться на
группу **`PROXY`**, которая содержит все узлы.

## Incy

### Где вводить

**Настройки → Подписка → Incy → Маршрутизация**:

1. включите **Включить маршрутизацию**;
2. заполните **Правила маршрутизации**:
   - готовая ссылка `incy://routing/onadd/<base64>` — тот же JSON, что и у
     Happ, закодированный в Base64;
   - **или одна HTTPS‑ссылка** на JSON‑файл. Панель превращает её в ссылку
     `incy://autorouting/onadd/<url>`, и приложение **само** периодически
     перекачивает профиль.

Профиль для Incy уходит строкой в **теле** подписки (только когда User‑Agent —
INCY). Заголовок `Routing` для Incy панель в этом случае не отправляет, чтобы
он не перебил профиль из тела.

### Формат JSON

Формат профиля Incy совпадает с форматом Happ — используйте те же поля
(`Name`, `RouteOrder`, `DirectSites`, `DirectIp`, `ProxySites`, `BlockSites`,
`DomainStrategy` и т. д., см. таблицу выше):

```json
{
  "Name": "RU bypass",
  "GlobalProxy": "true",
  "RouteOrder": "block-proxy-direct",
  "DirectSites": ["geosite:private", "domain:ru", "geosite:category-ru"],
  "DirectIp": ["geoip:ru", "geoip:private"],
  "ProxySites": [],
  "ProxyIp": [],
  "BlockSites": ["geosite:category-ads-all"],
  "BlockIp": [],
  "DomainStrategy": "IPIfNonMatch"
}
```

Закодированная форма: `incy://routing/onadd/<base64 от JSON>` (кодирование
как в примере для Happ).

> Если поле Incy пустое, Incy получает общий профиль **JSON‑подписки**
> (`subJsonRoutingRules`). Поле Happ Incy не читает.

### Остальные вкладки Incy

Вкладки **Приложение**, **Баннеры**, **Приватность** и **Сеть** не относятся к
маршрутизации: они задают заголовки управления приложением (описание профиля,
баннер, скрытие URL, фрагментация и т. д.) и отправляются только при включённом
**Автоопределении заголовков Incy**.

## Какой формат выбрать

| Нужно | Решение |
| ----- | ------- |
| Один набор правил для Happ и Incy | Один JSON, вставить в Happ как `happ://...`, в Incy как `incy://...` либо дать обоим одну HTTPS‑ссылку на JSON. |
| Правила для Clash/Mihomo | Отдельный YAML. JSON и YAML взаимно не конвертируются. |
| Менять правила без правки панели | Постоянная raw‑ссылка (gist, репозиторий) в нужном поле. |
| Проверить результат | Откройте подписку клиентским User‑Agent (`curl -A "Happ/1.0"`, `-A "INCY/1.0"`, `-A "clash.meta"`) и посмотрите заголовок `Routing` / тело ответа. |

## Частые проблемы

- **Правила не применились, в логе «Remote happ routing refresh from … failed»**
  (или `clash`; для профиля JSON-подписки — «remote source unavailable»).
  Ссылка ещё не
  скачана (первая загрузка идёт в фоне — обновите подписку через минуту) или
  источник вернул невалидный файл.
- **Файл отклонён из‑за размера.** Happ — максимум 8 КиБ после кодирования в Base64
  (около 6 КиБ JSON); вынесите длинные
  списки в `geosite`/`geoip` категории или в `rule-providers` (Clash).
- **Ошибка `references unknown proxy or group`.** Правило или группа ссылаются
  на имя, которого нет в профиле. Используйте `PROXY`, `DIRECT`, `REJECT` или
  объявите группу в том же файле.
- **Ссылка на страницу gist не работает.** Нужен `raw`‑URL.
- **Clash for Windows игнорирует правила.** Эндпоинт `/clash-legacy/` не
  поддерживает пользовательскую маршрутизацию — используйте `/mihomo/`.
