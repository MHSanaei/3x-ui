Обратный прокси позволяет отдавать панель и подписку на аккуратном домене с
автоматическим HTTPS и скрывать реальные порты за портами 80/443. Хотите, чтобы
панель завершала TLS напрямую? Тогда получите сертификат через
[меню SSL `x-ui`](/docs/config/ssl-certificates).

## Встроенный реверс-прокси

В этом форке есть собственный реверс-прокси, поэтому в типичном случае Nginx
или Caddy не нужны вовсе. Включается в **Настройках → Реверс-прокси**. Это
один локальный TLS-слушатель, который маршрутизирует по пути:

| Путь запроса | Куда ведёт |
| --- | --- |
| Базовый путь панели | Панель |
| Путь подписки | Сервер подписок |
| Всё остальное | Сайт-заглушка |

Смысл именно в третьей строке. В связке с REALITY: укажите в fallback-поле
`target` REALITY-инбаунда `127.0.0.1:<порт реверс-прокси>` — и тот, кто
просканирует ваш `:443` без действующего ключа REALITY, увидит обычный сайт,
а не признак того, что здесь работает панель.

<Callout type="warn">
  Fallback REALITY — слепая ретрансляция байт: Xray не может их расшифровать,
  поэтому реверс-прокси обязан сам завершать настоящий TLS. Выберите
  **Вручную**, чтобы использовать файлы сертификата самой панели, или
  **Автоматически**, чтобы панель получила сертификат от Let's Encrypt.
  Автоматический режим использует HTTP-01, потому что порт 443 занят Xray:
  порт 80 должен быть свободен и доступен из интернета.
</Callout>

Заглушкой может быть одна из встроенных в панель страниц, ваш статический сайт,
загруженный zip-архивом (`index.html` в корне или внутри одной папки, до
64 МиБ), либо прокси на сайт, который вы уже где-то размещаете.

<Callout type="info">
  Если неверно настроенный реверс-прокси закрыл вам доступ к панели,
  отключите его по SSH командой `x-ui setting -disableFrontProxy` и
  перезапустите панель. Команда пишет напрямую в базу и не требует запущенной
  панели.
</Callout>

Nginx или Caddy по-прежнему нужны там, где встроенный реверс-прокси
сознательно ничего не умеет: маршрутизация других сервисов помимо этой
панели, CDN-фронтинг, ограничение частоты запросов и правила доступа по путям.

## Nginx + сертификат

С Nginx получите сертификат с помощью `certbot` (или `acme.sh`) и укажите его в
блоке server:

```bash title="certbot"
certbot certonly --nginx -d panel.example.com
```

Перезагрузите Nginx после установки сертификата и настройте автоматическое
продление (`certbot renew` по умолчанию запускается по таймеру).

## Caddy

Caddy получает и продлевает сертификаты за вас — направьте Caddyfile на панель,
и всё просто заработает:

```text title="Caddyfile"
panel.example.com {
    reverse_proxy 127.0.0.1:2053
}
```

## Советы

- Сохраняйте **базовый веб-путь** панели даже за прокси; это эшелонированная защита.
- Если вы завершаете TLS на прокси, возможно, стоит выставить `XUI_SKIP_HSTS=true` на
  панели — см. [справочник по переменным окружения](/docs/reference/env-vars).
- Проксируйте также сервер [подписки](/docs/config/subscription), чтобы его содержимое
  отдавалось по HTTPS.
